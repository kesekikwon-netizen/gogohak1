# 시굴 전 종합 평가 설계도 (처음부터 끝까지)

요청 기록: docs/intent/2026-10-23-survey-prior-assessment.md
보는 쪽 그림: docs/design/2026-10-23-survey-assessment/index.html (같은 내용을 그림으로 그린 것)
상태: 사용자가 「추천대로」로 열린 질문을 확정했다(2026-10-23). 코드는 아직 바꾸지 않았다.

## 1. 한 줄 목표

조사구역을 그리고 반경(500m / 1000m)을 정하면, 그 안의 주변유적마다 **GIS 실측값 + 발굴조사보고서 + 논문(DBpia)** 을 한 묶음으로 모아, 시굴 들어가기 전에 알아야 할 것을 **확실한 근거로만** 쓴 평가서(HWPX + PDF)를 낸다.

## 2. 지금 상태 (직접 확인한 것)

| 항목 | 확인한 사실 | 영향 |
|---|---|---|

| 근거를 모으는 길 | 셋이고 서로 이어지지 않는다: 앱의 전국 보고서 DB(`LocalReportRag`), 앱 안 DBpia 직접 호출(`KaGeminiBridgeClient`), 독립 경주 DB(`scripts/gyeongju_rag`). | 같은 질문에 답이 달라질 수 있다. |

## 3. 핵심 원칙

1. **연결은 코드가, 판단은 AI가.** 어느 보고서가 어느 유적 것인지 잇는 일(유산코드, 허가번호, 유적명, 소재지)은 확정적으로 코드가 한다. AI는 모인 근거를 읽고 종합·판단·집필한다.
2. **유적마다 근거 꾸러미 하나.** 모든 것을 서로 잇지 않고, 꾸러미를 중심에 둔다. AI는 꾸러미만 읽고 쓴다.
3. **AI가 없어도 근거표는 나온다.** AI·인터넷·DBpia 로그인이 없어도 GIS 표와 보고서 근거표는 만들어진다. AI는 그 위의 종합만 더한다.
4. **모든 문장에 근거 번호.** 근거 번호가 없는 주장은 평가서에 들어가지 못한다.
5. **정확해야 하는 그림은 GIS가, 설명 그림은 AI가.** 위치·거리·축척이 있는 그림은 GIS가 그린다. 나노바나나 프로는 개념 모식도만 그리고 「모식도(실측 아님)」를 박는다.

## 4. 사용자 흐름 (현장)

1. 조사구역을 그린다(지금 앱 그대로).
2. 반경을 고른다: 500m / 1000m.
3. 주변유적이 자동으로 뽑힌다(지금 앱 그대로).
4. 「평가서 만들기」를 누른다. 진행 상황이 단계 이름으로 보인다.
5. 유적별 근거를 확인한다: 어떤 보고서 몇 쪽, 어떤 논문, 무엇이 비어 있는지.
6. 평가서 미리보기를 읽고, 고칠 곳은 글로 요청한다(예: 「고찰에 ○○ 연계 추가」).
7. HWPX와 PDF로 내보낸다. 출고 검사에 걸리면 내보내기 전에 목록으로 알려 준다.

## 5. 시스템 구조

세 곳이 파일(JSON)로 주고받는다. 처음에는 파일, 안정되면 MCP를 얹는다.

```
[앱: GIS + 화면]              [근거 저장소: 읽기 전용]        [Antigravity SDK]
 조사구역·반경·주변유적  →    보고서 전문(쪽 번호)            꾸러미 조립
 사실 묶음(JSON) 내보내기      논문 서지·초록                  종합·연계성·집필
 평가서 미리보기·내보내기 ←    DBpia AI 답변                   편집(용어·표·중복)
 출고 검사                      (수집기가 채움)                 나노바나나 프로 모식도
```

- 앱의 몫: GIS(주변유적, 반경, 이격거리·방위·해발), 화면, 출고 검사.
- 근거 저장소의 몫: 하나로 합친 읽기 전용 저장소. 처음 범위는 경주(자료가 있는 곳).
- SDK의 몫: 수집(저장소 채우기), 꾸러미 조립, 종합, 집필, 편집, 모식도.
- 앱 안 DBpia 직접 호출(`KaGeminiBridgeClient`)은 화면에서 숨기고 코드는 둔다. 수집은 DBpia AI를 통해서만 한다.

## 6. 계약 세 가지 (JSON)

### 6.1 사실 묶음 (앱 → SDK)
`GisFactHarness::Ledger`를 그대로 JSON으로 낸다. 앱이 계산한 값만 담는다.
- `survey`: 제목, 작업좌표계, 면적(㎡), 반경(m), 지역
- `cards[]`: `id`(G1…), `kind`, `subject`, `attribute`, `value`, `unit`, `distanceMeters`, `direction`, `quote`
- `sites[]`: 유적명, 데이터셋, 이격거리, 방위, 유산코드, 허가번호, 조사기관, GIS 서지(보고서명, 연도), 시대
- `uncollected[]`: 값이 없는 도메인(`soil`, `paleo_landform`, `dem`, `geology`). 이 목록에 있는 것은 수치를 쓰지 못한다.

### 6.2 근거 항목 (저장소 → SDK, SDK → 평가서)
- `id`(E1…), `siteRef`, `kind`(보고서 / 논문 / DBpia AI), `source`(보고서명·연도·기관 또는 논문 서지), `page`, `text`(원문 그대로), `status`
- `status` 네 가지: **동일 보고서 확인 / 참고(다른 보고서·같은 동·리) / 스캔본(직접 대조 필요) / 미수록**. 기호(✓ △ ◌ ○)는 말과 함께, 범례를 두고 쓴다. 기호만 단독으로 나오지 않게 한다.

### 6.3 평가 결과 (SDK → 앱)
- `sections[]`: `key`, `title`, `claims[]`
- 문장마다 `text`, `evidenceIds[]`, `type`(**사실** 근거가 직접 말함 / **추정** 근거에서 이끌어 낸 판단 / **자료 없음**)
- 인용할 수 있는 번호: 보고서·논문 근거 `E…`, GIS 실측 카드 `G…`, GIS 유적 기록(공식 서지 포함) `S…`. `G`·`S` 번호는 사실 묶음이 낸다(2026-10-23 구현하며 보강).
- `figures[]`: 모식도 파일, 만든 방법, 근거 번호, 「모식도(실측 아님)」 표시
- `gaps[]`: 부족한 자료와 현장에서 확인할 것

## 7. 결과물: 시굴 전 종합 평가서

| 장 | 내용 | 주된 근거 |
|---|---|---|
| 0 | 요약 한 쪽: 시굴 전에 꼭 알아야 할 것 5가지 | 아래 장 전체 |
| 1 | 조사구역 개요: 면적, 좌표계, 지형·해발, 토양·지질(있을 때) | GIS |
| 2 | 반경별 주변유적(500m, 1000m): 표와 분포 약도 | GIS |
| 3 | 유적별 카드: 시대, 유구, 층위, 출토 + 근거 쪽 번호 | 보고서 |
| 4 | 연계성: 조사구역과 어떤 유적이 왜 이어지는가(사실과 추정을 나눠 표시) | 보고서 + 논문 |
| 5 | 시굴 참고: 확인된 층위·유구 깊이, 예상 시대·유구, 주의할 구역 (판단은 「참고」 표시) | 보고서 + 논문 |
| 6 | 부족한 자료와 현장에서 확인할 것 (체크리스트) | `uncollected`, 미수록 |
| 7 | 참고문헌: 보고서, 논문 | 근거 항목 |
| 부록 | A 근거 대장(모든 문장 번호 → 출처·쪽), B 모식도 사용 내역 | 근거 항목 |

지금 만드는 조사 후 보고서 틀(Ⅰ~Ⅵ장)은 버리지 않는다. 「보고서 초안」 모드로 분리해 두고 같은 근거를 재사용한다(2차).

## 8. 출고 검사 (제출물 품질을 지키는 문)

앱이 내보내기 직전에 검사하고, 걸리면 목록을 보여 주고 한 번 묻는다(제출 꾸러미와 같은 규칙: 막지 않고 알린다). **구현됨(2026-10-23)**: 한글 문서 저장 직전 `confirmExportClean`이 금지어·자리표시자·깨진 글자·장식 문자를 찾는다. 근거 번호 없는 문장 등 평가서 규칙은 `validateAssessment`가 맡는다.
- 금지어: RAG, SDK, 피처, 슬롯, 누름틀, Antigravity, 하네스, 자리표시자(`*_SLOT`), 깨진 글자, 장식 문자(┏ ┓ ┗ ┛).
- 근거 번호 없는 사실 문장.
- `uncollected`에 있는 도메인의 수치.
- 비어 있는 장(「자료 없음」 문장도 없는 경우).
- 나노바나나 그림에 「모식도(실측 아님)」 표시가 없는 경우.

## 9. 나노바나나 프로 사용 규칙

- 쓰는 곳: 층위 대비 모식도, 유구 개념도처럼 **설명용 그림**만.
- 입력: SDK가 근거 항목과 사실 묶음에서 만든 구조화 지시(시대, 층위 순서, 깊이). 자유 서술 금지.
- 출력: 그림 파일 + 사용한 지시문 + 근거 번호를 부록 B에 남긴다.
- 사람이 확인(채택/버림)한 그림만 문서에 들어간다.
- 위치·거리·축척이 있는 그림에는 쓰지 않는다. 그건 GIS가 그린다.

## 10. 앱 정리 (쓰레기·이상한 문자)

1. **글자 사전**: 화면과 문서에서 쓰는 말을 한 표로 정한다(예: RAG → 「보고서 근거」, GIS 서지 → 「공식 서지」, 누름틀 → 「양식 칸」). 사용자에게 보이는 곳은 이 말만 쓴다.
2. **자리표시자 제거**: `RAG_CITATION_SLOT`, `[RAG 연결 슬롯 대기 중 …]` 같은 글이 문서에 들어가지 않게 한다. 근거가 없으면 「자료 없음」을 쓴다.
3. **기호 규칙**: ✓ △ ◌ ○ 는 항상 말과 함께 쓰고(예: 「✓ 동일 보고서」) 범례를 둔다. 기호만 단독으로 쓰지 않는다. ┏ ┓ ┗ ┛ 같은 장식 문자는 쓰지 않는다. ※ 는 주석 표시로 쓸 수 있다. (2026-10-23 확인: 현재 코드는 이미 기호 옆에 말이 있고 범례도 있어 이 규칙으로 충분하다.)
4. **기관 이름은 설정**: 「동국문화재연구원」 고정 문구를 설정값으로 옮긴다.
5. **시험으로 잠근다**: `ui_terms`를 넓혀 금지어가 소스의 화면 글자와 생성 문서에 다시 들어오면 실패하게 한다.

## 11. 단계(마일스톤)와 끝났다는 기준

| 단계 | 하는 일 | 끝났다는 기준 (확인 방법) |
|---|---|---|
| M0 정리 | 글자 사전, 자리표시자·장식 제거, 금지어 시험, 진행 표시를 실제 작업과 맞추기 | 금지어 0건(시험), 생성한 문서에서 자리표시자 0건, 진행 표시에 하지 않은 일이 없다 |
| M1 계약 | JSON 세 가지 + 샘플 + 앱의 사실 묶음 내보내기 | 스키마 검증 시험 통과, 샘플 파일 저장 |
| M2 저장소 | 근거 저장소 하나로 읽기. 앱 안 DBpia 직접 호출 닫기(완료: 단추 숨김 + 요청 자동 시작 제거, 시험으로 잠금) | 경주 유적 3곳에서 같은 질문에 같은 근거, 화면에 DBpia 직접 단추 없음 |
| M3 SDK 최소 | 꾸러미 조립 + 규칙 기반 뼈대 평가(AI 없이) | AI 끈 상태에서 평가서 0·1·2·3·6·7장이 나온다 (**뼈대 코드 완료**: `AssessmentSkeleton`, 시험 `assessment_skeleton`. 파일 내보내기 완료: 보고서 화면 저장 메뉴의 「평가 자료 저장…」이 `평가 자료/` 폴더에 `facts.json`, `evidence.json`, `assessment.json`을 쓴다. 보고서 화면의 「평가」 보기에서 장·문장·종류·근거 번호를 읽을 수 있다) |
| M4 종합·집필 | Antigravity가 4·5장과 요약을 쓰고 근거 번호를 붙인다 | 근거 번호 없는 사실 문장 0건(출고 검사) |
| M5 모식도 | 나노바나나 프로로 모식도, 채택 절차, 부록 B | 모든 그림에 표시와 근거 번호 |
| M6 출고 검사 + 현장 시험 | 경주 시굴지(성동동·황오동)로 평가서를 만들고 사용자가 읽는다 | 사용자가 보고 「쓸 만하다」고 답함 + 아래 합격 기준 |
| M7 Windows 마무리 | HWPX·PDF 열기, CI 초록, 포터블 | Windows에서 열림, CI 초록 |

**합격 기준(M6):** ① 모든 주장의 출처와 쪽을 눌러서 확인할 수 있다 ② 빈 곳은 「자료 없음」과 이유가 있다 ③ 금지어·자리표시자 0건 ④ 부족한 자료 목록이 현장에서 쓸 만하다 ⑤ 사용자가 시굴 전에 읽고 싶은 순서로 되어 있다.

## 12. 정한 것과 남은 것

정한 것(사용자 「추천대로」):
- 앱 안 DBpia 직접 단추는 SDK가 오기 전까지 숨긴다. 코드는 둔다.
- 첫 버전은 데이터가 있는 경주만 한다.
- 평가서 항목은 7절의 표로 한다.
- 안티그라비티 SDK가 AI 처리를 맡는다.

정한 것(기술 결정, 내가 정함):
- 처음 주고받는 방식은 파일(JSON). MCP는 나중.
- 수집은 미리 해서 저장소에 쌓고, 현장에서는 저장소만 읽는다(DBpia 로그인 없이도 동작).
- 조사 후 보고서 틀은 「보고서 초안」 모드로 분리해 보존한다.

남은 것(사용자 확인이 필요해지는 시점에 묻는다):
- 기관 이름·표지 양식(M0).
- 평가서 5장(시굴 참고)에서 어디까지 권고로 써도 되는지(M4 전).

## 13. 하지 않는 것

- 다른 터미널에서 진행 중인 수집(`scripts/gyeongju_rag/`, `/mnt/data-drawing/gyeongju_rag/`)은 건드리지 않는다.
- 유료 원문 PDF를 내려받지 않는다. 결제 행위를 하지 않는다.
- AI가 유적과 보고서를 잇지 않는다.
- 근거 없는 수치·시대·깊이를 쓰지 않는다.
- GIS 쪽 기능은 이 설계 때문에 바꾸지 않는다.
