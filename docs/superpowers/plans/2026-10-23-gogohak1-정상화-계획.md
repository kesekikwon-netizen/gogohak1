## 단계

각 단계는 끝난 뒤 커밋·푸시한다. 사용자 확인 기준은 「끝났다는 기준」이다.

### 1단계 — 작업 합치기 (작업 잃지 않기)
- `/home/kwon/hgis`의 커밋 3개와 미커밋 수정을 읽기만 해서 목록으로 만들고(`git status`, `git diff --stat`), 사용자에게 보여 준다. 미커밋 수정은 이 단계에서 버리거나 되돌리지 않는다.
- `/home/kwon/hgis`가 gogohak1을 `origin`으로 쓰게 하고(`git remote set-url`), 사본의 `f035f59`를 받아 합친 뒤 푸시한다. 사본은 이후 쓰지 않는다.
- **끝났다는 기준:** gogohak1 `main`에 경주 RAG 커밋이 보이고, `git status`가 깨끗하며, 폴더 하나만 남는다.

### 2단계 — Windows 빌드 복구 (CI 설정 오류)
- `dev-env.lock.json`에 이미 `zlib`이 있어도 개발용 파일(헤더·`.lib`)이 설치 목록에 없을 가능성이 크다. OSGeo4W의 정확한 패키지 이름을 확인해 설치 목록(CI `osgeo4wPackages`)에 추가하거나, 필요 없으면 `find_package(ZLIB)` 대신 Qt 내장 zlib를 쓴다. Qt·GDAL API와 같이 CMake 변경 전 context7로 해당 버전 문서를 확인한다.
- CMake 변경 후 CI 설정 단계 → 빌드 → 시험 순서로 하나씩 초록으로 만든다. 이 단계에서는 CI 결과만 보고 실패 원인을 하나씩 고친다(한 번에 하나, 세 번 실패하면 중단하고 보고).
- **끝났다는 기준:** gogohak1 CI의 「Windows build and tests」 설정·빌드·smoke 초록.

### 3단계 — 리눅스를 일상 개발 환경으로
- `CMakePresets.json`에 `linux` 프리셋 하나(`build-linux`, Ninja, 경로는 상대 경로·환경변수만)로 설정하고, 첫 빌드 한 줄 명령을 `docs/agent/strata-reference.md`에 적는다.
- `CMakeLists.txt:132`의 개인 경로 `/home/kwon/Disks/han/...`는 CMake 변수(`OPENHWP_SDK_ROOT`)로만 받고 기본은 `third_party/OpenHwpSDK`로 고정한다.
- 리눅스 빌드가 되는지, 어떤 시험이 리눅스에서 돌아가는지 직접 돌려 「리눅스에서 도는 시험 목록」을 `docs/testing-map.md`에 적는다. 돌지 않는 것은 이유와 함께 「Windows 전용」으로 표시한다(QGIS 렌더·WebEngine·OSGeo4W 경로).
- **끝났다는 기준:** 새로 clone한 폴더에서 한 줄 명령으로 `ka-hgis`와 보고서 시험(`hwp_survey_report`)이 빌드·통과한다. 결과 로그를 보고에 붙인다.

### 4단계 — 규칙·검사 틀 맞추기
- `commit-gate.mjs`가 `build-linux/`(리눅스 산출물과 `Testing/Temporary/LastTest.log`)도 증거로 인정하게 한다. 단 Windows 전용 파일을 건드린 커밋은 Windows CI 결과도 요구한다는 규칙은 유지한다.
- `AGENTS.md`와 `CLAUDE.md`를 하나로 통일: 정본은 `CLAUDE.md`, `AGENTS.md`는 가리키기만 한다. 포함할 내용: 저장소=gogohak1, 평소 리눅스·마무리 Windows, 푸시 규칙(ff-only), 보고서 기능 방향(0단계 답).
- **끝났다는 기준:** 리눅스에서 만든 사소한 `src/` 수정이 검사 통과 후 커밋되고, 두 규칙 파일에 충돌이 없다.

### 5단계 — 시험 복원과 보고서 코드 정리
- 지워진 시험 두 개(HWPX 양식 불러오기·누름틀 치환, 사용자 요청 일괄 치환)를 되살린다. 되살린 이유는 커밋 메시지에 쓴다.
- 지역 분류(`LocalReportRag::classifyMacroRegion`)를 글자 포함 검사에서 「경로의 도·시군구 폴더 이름」 우선으로 바꾸고, 못 정하면 「미분류」로 둔다(경기도로 기본 처리 금지). 고성·광주·영동 시험을 먼저 쓰고(실패 확인) 고친다.
- 파일 쪼개기: 300줄에 붙은 5개 파일을 역할별로 나누고(UI 배치 / 동작 / 문헌수집 로그인 뷰), 한 줄 여러 문장 코드를 풀어 쓴다. `LayerOps.cpp`의 `NoIndex` 줄은 원래 모양으로 되돌린다. 줄 수 기준선은 올리지 않는다.
- DBpia 쿠키: 기본 비영속 프로필, 켜면 영속. 프로필 이름은 Gemini와 분리.
- SQLite 직접 선언을 `<sqlite3.h>` 포함으로 바꾼다(CMake에서 헤더 경로 확인).
- **끝났다는 기준:** 리눅스 시험 통과 + Windows CI 초록 + 줄 수 검사 통과 + 지역 오분류 시험 3건 통과.

### 6단계 — Windows 마무리 (마지막 개발)
- 현장 Windows PC에서 `git pull` → 첫 빌드 → smoke → 「Strata (개발)」 바로가기 갱신.
- 현장 확인 목록(사용자가 눈으로): ① 앱이 열리고 홈 화면만 보인다 ② 조사 열기 → 그리기 → 저장(Ctrl+S) ③ 제출 꾸러미 만들기 ④ 보고서 탭이 열린다 ⑤ 지도 확대·이동 때 멎지 않는다(`NoIndex` 영향 확인).
- 문제가 있으면 `docs/ERROR_REGRESSION.md`에 행을 추가하고 시험을 더한다.
- **끝났다는 기준:** Windows CI 전체 초록 + 현장 확인 목록 5개를 사용자가 확인.

### 7단계 — 문서 정리
- README·`docs/other-pc-setup.md`에 리눅스 설치와 Windows 설치를 따로 적는다. `docs/HANDOFF.md`는 현재 상태 한 쪽으로 줄이고 옛 기록은 `docs/archive/`로 보낸다.
- **끝났다는 기준:** 새 사람이 README만 보고 리눅스 빌드까지 따라 한다.

## 위험과 순서 이유
- 1단계가 먼저인 이유: 정본 폴더의 미커밋 작업이 사라지면 되돌릴 수 없다.
- 2단계를 3단계보다 먼저 한 이유: 최종 납품이 Windows이므로 Windows 빌드가 깨져 있으면 이후 모든 변경을 검증할 수 없다.
- 리눅스 시험이 통과해도 Windows에서 깨질 수 있다(경로·인코딩·WebEngine). 그래서 단계마다 CI를 마지막 판정으로 쓴다.
