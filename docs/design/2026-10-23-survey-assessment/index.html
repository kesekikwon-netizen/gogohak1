STRATA · 설계도 · 2026-10-23 · 코드는 아직 바꾸지 않음

시굴 전 종합 평가 설계도

조사구역을 그리고 반경을 정하면, 주변유적마다 GIS 실측값과 발굴조사보고서, 논문을 한 묶음으로 모아 확실한 근거로만 쓴 평가서를 냅니다. 이 페이지는 처음부터 끝까지의 설계를 한곳에 둔 것이고, 단계가 끝날 때마다 현황 표지를 고쳐 다시 올립니다.

1 목표와 결과물

사용자가 시굴에 들어가기 전에 읽는 문서 한 권

평가서가 답해야 하는 세 가지

  1. 이 지역에서 시굴하기 전에 내가 알아야 할 것은 무엇인가
  2. 시굴을 어떤 정보로 해야 하고, 어떤 정보가 더 있어야 하는가
  3. 어떤 유적과 연계성을 알아야 하는가

나오는 파일

  • 평가서 .hwpx 와 .pdf
  • 부록: 모든 문장의 근거 대장, 모식도 사용 내역
  • 근거는 보고서 쪽 번호, 논문 서지까지 눌러서 확인 가능

2 지금 상태 직접 확인한 것

문제는 만들어 둔 조각이 아니라, 조각 사이에 합의된 약속이 없다는 점입니다.

항목확인한 사실영향

가짜 진행 표시「작성 시작」 뒤 0.32초 타이머가 단계를 올리며 「사실·인용 교차검증」, 「집필」, 「작성 완료」를 보여 주지만 실제로는 4단계까지 문서를 쌓을 뿐이다하지 않은 일을 했다고 보여 준다. 고침: 실제 4단계로 바꾸고 시험이 지킨다

기호✓ △ ◌ ○ 가 설명 없이 표에 들어가고 ┏ ┓ 같은 장식도 있다뜻 모를 글자
이미 잘 된 것, 버리지 않습니다. GisFactHarness::Ledger(앱이 계산한 값만 담고 없는 자료는 잠금), 근거 4단계 라벨, 「임의로 채우지 않았습니다」 원칙. 이것이 계약의 뼈대가 됩니다.

3 핵심 원칙

1. 연결은 코드가, 판단은 AI가어느 보고서가 어느 유적 것인지는 유산코드·허가번호·유적명·소재지로 코드가 확정한다. AI는 모인 근거를 읽고 종합·집필한다.
2. 유적마다 근거 꾸러미 하나모든 것을 서로 잇지 않는다. 꾸러미를 중심에 두고 AI는 꾸러미만 읽고 쓴다.
3. AI가 없어도 근거표는 나온다AI·인터넷·DBpia 로그인이 없어도 GIS 표와 보고서 근거표는 만들어진다.
4. 모든 문장에 근거 번호근거 번호가 없는 주장은 평가서에 들어가지 못한다.
5. 정확한 그림은 GIS, 설명 그림은 AI위치·거리·축척이 있는 그림은 GIS가 그린다. 나노바나나 프로는 개념 모식도만 그리고 「모식도(실측 아님)」를 박는다.

4 사용자 흐름 현장

앞 세 단계는 지금 앱 그대로입니다. 앱 SDK

  1. 조사구역을 그린다
  2. 반경을 고른다 (500m / 1000m)
  3. 주변유적이 자동으로 뽑힌다
  4. 「평가서 만들기」 — 단계 이름으로 진행이 보인다
  5. 유적별 근거 확인: 어떤 보고서 몇 쪽, 어떤 논문, 무엇이 비었나
  6. 미리보기를 읽고 고칠 곳은 글로 요청
  7. 출고 검사 통과 후 HWPX · PDF로 내보내기

5 시스템 구조

세 곳이 파일(JSON)로 주고받습니다. 처음에는 파일, 안정되면 MCP를 얹습니다.

앱 안 DBpia 직접 호출(KaGeminiBridgeClient)은 화면에서 숨기고 코드는 둡니다. 수집은 DBpia AI를 통해서만 하며, 현장에서는 DBpia 로그인 없이 저장소만 읽습니다.

6 계약 세 가지 JSON

이 세 모양만 지키면 앱, 저장소, SDK를 따로 만들어도 맞물립니다.

앱 → SDK 사실 묶음

지금의 GisFactHarness::Ledger를 그대로 JSON으로 냅니다.

{
  "survey":  { "title": "경주 성동동 시굴", "crs": "EPSG:5187", "areaM2": 1840, "radiusM": 500, "region": "경주시" },
  "cards":   [ { "id": "G1", "kind": "nearby_heritage", "subject": "경주 황남동 유적",
                 "attribute": "이격거리", "value": "142", "unit": "m", "direction": "북서" } ],
  "sites":   [ { "name": "경주 황남동 유적", "heritageCode": "…", "permitNo": "…",
                 "institution": "…", "bibliography": { "title": "…", "year": 2019 } } ],
  "uncollected": [ "soil", "paleo_landform", "dem", "geology" ]   // 이 목록은 수치를 쓸 수 없다
}

저장소 → SDK 근거 항목

{ "id": "E12", "siteRef": "경주 황남동 유적", "kind": "report",
  "source": { "title": "…발굴조사보고서", "year": 2019, "institution": "…" },
  "page": 78, "text": "원문 그대로",
  "status": "same_report" }   // same_report | reference | scan | missing

상태 네 가지: 동일 보고서 확인 참고 스캔본(직접 대조) 미수록. 기호(✓ △ ◌ ○)는 말과 함께, 범례를 두고 씁니다. 기호만 단독으로 나오지 않게 합니다.

SDK → 앱 평가 결과

{ "sections": [ { "key": "link", "title": "연계성",
      "claims": [ { "text": "…", "evidenceIds": ["E12", "S1"], "type": "fact" } ] } ],
  "figures":  [ { "file": "strata_1.png", "label": "모식도(실측 아님)", "evidenceIds": ["E12"] } ],
  "gaps":     [ "토양 자료 없음 — 현장에서 확인" ] }   // type: fact(사실) | inference(추정) | none(자료 없음)
// 인용 번호: E 보고서·논문 근거 · G GIS 실측 카드 · S GIS 유적 기록(공식 서지 포함)

7 평가서 구성

지금의 조사 후 보고서 틀(Ⅰ~Ⅵ장)은 버리지 않고 「보고서 초안」 모드로 분리해 같은 근거를 재사용합니다(2차).

장내용주된 근거
0 요약시굴 전에 꼭 알아야 할 것 5가지, 한 쪽아래 장 전체
1 조사구역 개요면적, 좌표계, 지형·해발, 토양·지질(있을 때)GIS
2 반경별 주변유적500m, 1000m 표와 분포 약도GIS
3 유적별 카드시대, 유구, 층위, 출토 + 근거 쪽 번호보고서
4 연계성조사구역과 어떤 유적이 왜 이어지는가. 사실과 추정을 나눠 표시보고서 + 논문
5 시굴 참고확인된 층위·유구 깊이, 예상 시대·유구, 주의할 구역. 판단은 「참고」 표시보고서 + 논문
6 부족한 자료현장에서 확인할 것 체크리스트uncollected, 미수록
7 참고문헌보고서, 논문근거 항목
부록A 근거 대장(문장 번호 → 출처·쪽), B 모식도 사용 내역근거 항목

8 출고 검사 제출물 품질을 지키는 문

내보내기 직전에 앱이 검사하고, 걸리면 목록을 보여 주고 한 번 묻습니다(제출 꾸러미와 같은 규칙). 한글 문서 저장에는 이미 연결했습니다.

막는 것

  • 금지어: RAG, SDK, 피처, 슬롯, 누름틀, Antigravity, 하네스, *_SLOT
  • 깨진 글자, 장식 문자(┏ ┓ ┗ ┛)
  • 근거 번호 없는 사실 문장
  • uncollected에 있는 도메인의 수치
  • 「자료 없음」 문장도 없이 비어 있는 장
  • 「모식도(실측 아님)」 표시 없는 AI 그림

이렇게 막는다

문서를 만든 뒤 글자를 훑어 검사합니다. 소스의 화면 글자는 ui_terms 시험이 같은 금지어를 지킵니다. 그래서 새 기능이 옛 습관으로 다시 쓰레기를 넣어도 시험에서 걸립니다.

9 나노바나나 프로 설명 그림 전용

쓰는 곳

  • 층위 대비 모식도
  • 유구 개념도

위치·거리·축척이 있는 그림에는 쓰지 않습니다. 그건 GIS가 그립니다.

규칙

  • 입력: 근거 항목과 사실 묶음에서 만든 구조화 지시(시대, 층위 순서, 깊이). 자유 서술 금지
  • 출력: 그림 + 지시문 + 근거 번호를 부록 B에 남김
  • 사람이 채택한 그림만 문서에 들어감
  • 모든 그림에 「모식도(실측 아님)」

10 앱 정리 쓰레기 · 이상한 문자

지금바꾸는 것
RAG, GIS 서지, 누름틀, 피처ID글자 사전 한 표로 통일: 「보고서 근거」, 「공식 서지」, 「양식 칸」 …. 사용자에게 보이는 곳은 이 말만 쓴다
RAG_CITATION_SLOT 등 자리표시자문서에 들어가지 않게 한다. 근거가 없으면 「자료 없음」과 이유

11 단계와 합격 기준

현황 표지는 단계가 끝날 때마다 고쳐서 다시 올립니다. 마지막 갱신: 2026-10-23, M0 진행 · M1 완료. 안티그라비티 SDK와 RAG 수집은 기다리는 중이라 지금 할 수 있는 것만 진행합니다.

단계하는 일현황끝났다는 기준 (확인 방법)
M0 정리글자 사전, 자리표시자·장식 제거, 금지어 시험, 진행 표시를 실제 작업과 맞추기진행 개발 용어 37곳 · 자리표시자 · 장식 문자 · 가짜 진행 표시 정리 완료. 남음: 기관 이름 설정화금지어 0건(시험), 생성 문서의 자리표시자 0건
M1 계약JSON 세 가지 + 샘플 + 앱의 사실 묶음 내보내기완료 함수·검사기·시험·샘플 (화면 연결은 M3)스키마 검증 시험 통과, 샘플 파일 저장
M2 저장소근거 저장소 하나로 읽기, 앱 안 DBpia 직접 호출 닫기진행 직접 호출 닫기 완료(시험으로 잠금), 저장소 통합은 수집 완료 후경주 유적 3곳에서 같은 질문에 같은 근거, 직접 단추 없음
M3 SDK 최소꾸러미 조립 + 규칙 기반 뼈대 평가(AI 없이)진행 AI 없는 뼈대 코드·시험 완료 + 「평가 자료 저장…」 메뉴로 파일 내보내기와 화면의 「평가」 보기 완료. AI 종합(4·5장)은 SDK를 기다림AI를 끈 상태에서 0·1·2·3·6·7장이 나온다
M4 종합·집필Antigravity가 4·5장과 요약, 근거 번호 부착미착수근거 번호 없는 사실 문장 0건(출고 검사)
M5 모식도나노바나나 프로, 채택 절차, 부록 B미착수모든 그림에 표시와 근거 번호
M6 현장 시험경주 시굴지(성동동·황오동)로 평가서를 만들고 사용자가 읽는다미착수사용자가 「쓸 만하다」고 답함 + 아래 합격 기준
M7 Windows 마무리HWPX · PDF 열기, CI 초록, 포터블미착수Windows에서 열림, CI 초록
M6 합격 기준 다섯 가지
  1. 모든 주장의 출처와 쪽을 눌러서 확인할 수 있다
  2. 빈 곳은 「자료 없음」과 이유가 있다
  3. 금지어·자리표시자가 0건이다
  4. 부족한 자료 목록이 현장에서 쓸 만하다
  5. 사용자가 시굴 전에 읽고 싶은 순서로 되어 있다
정직한 판정: 지금 상태로는 결과물이 만족스럽지 않습니다(2절). 이 설계대로 M0~M6을 마치면 가능하지만, 조건이 둘 있습니다. ① 첫 버전은 자료가 있는 경주까지만 ② 시굴 참고(5장)는 사람이 확인하는 참고 의견이지 결론이 아님.

12 정한 것 · 남은 것

사용자가 정함 (추천대로)

  • Antigravity SDK가 AI 처리를 맡는다
  • 앱 안 DBpia 직접 단추는 SDK가 오기 전까지 숨김 (코드는 둠)
  • 첫 버전은 경주만
  • 평가서 항목은 7절 표대로

내가 정함 (기술)

  • 처음 주고받는 방식은 파일(JSON), MCP는 나중
  • 수집은 미리 해서 쌓고, 현장에서는 저장소만 읽음
  • 조사 후 보고서 틀은 「보고서 초안」 모드로 보존

남은 것 (그 시점에 묻는다)

  • 기관 이름·표지 양식 (M0)
  • 5장에서 어디까지 권고로 써도 되는지 (M4 전)

하지 않는 것

  • 다른 터미널의 수집(scripts/gyeongju_rag/)을 건드리지 않음
